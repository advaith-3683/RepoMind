      What RepoMind is

      RepoMind answers questions about an indexed public GitHub repository using retrieved source code. Answers include citations you can inspect, alongside a trace of the run. Sign in to ask questions and review proposed changes.

      Fast vs Agent mode

      Fast retrieves source once and makes one answer-model call. It is the default for codebase questions and cannot propose changes. Agent can search and read code over several steps, uses more model calls, and can propose a patch or issue. If Fast asks for clarification, Try Agent mode reuses your submitted question.

      How citations are verified

      The server checks that each cited file and line range overlaps source evidence retrieved during the run. Invalid citations are retried or removed; insufficient evidence can lead to clarification or a declined answer. Click a citation to inspect the indexed source lines. A verified citation identifies supporting evidence; it does not prove that every statement in an answer is correct.

      Guardrails

      Input checks, injection detection, a read-only tool allowlist, sandboxed file paths, secret redaction, and step, token, and time budgets limit what a run can do. Output checks verify citations and estimate groundedness. These checks have limits: unfamiliar attacks may evade detection, and benign questions may be flagged.

      Approving and publishing changes

      Agent proposals are suggestions. Review the server-computed diff, then approve, edit, or reject. Approval records your decision; publishing is a separate explicit action. Open pull request creates a branch and pull request when you have write access. Create issue opens an issue. Changes are never committed directly to the default branch. Copy or download the patch if publishing is unavailable.

      How to read the Evaluations page

      End-to-end answer rate measures answerable questions answered; correctly declined measures out-of-scope questions declined. File recall and keyword hit measure expected evidence coverage. Groundedness is a keyword-overlap proxy. Error rate, latency, and average tokens describe reliability and usage.

      Retrieval recall@1/3/5 measures expected file coverage among the top results; MRR measures the rank of the first relevant result. The ablation compares retrieval configurations on tune and held-out questions. Red-team counts show blocked attacks and benign prompts incorrectly flagged. Run history preserves invalid runs with their notes; the last row marks the current default. Read the Limits and Diagnostics before comparing runs.

      Worked example

      Question: Where does this repository validate a sign-in token?

      Follow the evidence: Ask in Fast mode, then open any returned citation to inspect the indexed source lines. Compare the explanation with that code. If the response says no supporting code was found, narrow the question or try Agent mode for additional lookups.

      A question alone does not approve or publish a change.

      Known limits

      • The published evaluation covers a single repository.
      • The golden set is small, with one run per configuration; differences of a few questions can be noise.
      • Groundedness is a keyword-overlap proxy, not a fact check or a measure of full answer faithfulness.
      • Results apply to the model and retrieval settings shown on the Evaluations page.
